# MVP範囲と検証計画

## 現在の到達点

完了しているのは、一次資料に基づく実現可能性評価、方式比較、設計、UI案、脅威整理、検証計画。アプリのPoC・製品実装・実機接続・性能測定は行っていない。以下の「ゲート」は**実装承認後に実施する計画**であり、合格済みの一覧ではない。

最初に最大の不確実性を小さいPoCで確認する。G1、G2、G3、G4、G7が成立しなければ、機能を増やす前に設計へ戻る。安全性を緩めて通過扱いにしない。

## MVPに含めるもの

| 領域 | 最小の完成範囲 | 完了条件 |
| --- | --- | --- |
| 接続 | iPhone1台・PC1台、自宅IPv4、ローカルTLS、登録と再認証、失効・停止 | G1〜G3合格 |
| アプリ | 登録アプリ起動、ウィンドウ一覧・切替・通常終了 | 標準権限の対象アプリで動き、保存確認／前面化失敗を表示できる |
| ファイル | 登録したローカルルート、一覧・現在フォルダ検索・作成・名前変更・同一ルート内コピー／移動・ごみ箱 | 拒否ケースと競合ケースに合格。単一選択 |
| 転送 | Filesからのアップロード、iPhoneへのダウンロード | 100 MiB以下の単一ファイルで完了／取消／切断を扱える |
| 入力 | iPhone側で日本語を確定して送信、Enter分離、明示的なテキストclipboard転送 | G4合格。対象不一致で誤送信しない |
| ターミナル | 固定の定型作業、PCで許可した自由PowerShellを1セッション | G6合格。非昇格、停止・期限・切断を扱える |
| 画面 | noVNC + UltraVNCによる1モニター操作、トラックパッド、クリック、ズーム | G7合格。LANにVNCポートが露出しない |
| 運用 | 接続表示、ローカル監査、ネットワーク変更停止、証明書更新案内、アンインストール手順 | G8合格 |

MVPはこれらを段階的に完成させる計画であり、自由シェルや画面操作を単に将来送りにして、要求を満たしたことにはしない。一方、利用者がそれらを有効化するまでは停止した状態で提供する。

## 将来拡張

| 候補 | 追加する条件 |
| --- | --- |
| Sunshine + Moonlight | noVNCの実測が不十分、または長時間の画面操作が増える。暗号化必須・外部通信なし・ポート制限を別途検証 |
| ブラウザタブ・特定アプリの専用操作 | よく使う操作が判明し、公式APIや拡張で安全に実行できる |
| 複数モニター | 1モニターで検証後、DPI混在・負座標・回転を追加検証 |
| ファイル複数選択・再開転送・大容量 | 誤操作と競合処理、容量制限、整合性の設計が完成したとき |
| Wake-on-LAN | 対応NIC・電源状態・ルーター制約を確認できる場合。外部からの起動は追加しない |
| WebAuthn等の再認証 | iCloudや外部認証基盤を必須とせず、実機で復旧・移行を検証できる場合 |
| ネイティブiPhoneクライアント | PWAの入力／証明書／性能制約が主要障害になり、署名・ビルド環境の条件を変更できる場合 |
| 永続的なバックグラウンドジョブ | 端末切断と実行継続の責任、停止、結果取得の設計を独立に行う |

対象外を維持するもの: WAN接続、ポート転送、外部relay、クラウド認証、管理者権限の遠隔取得、UAC回避、他人のPC操作、画面の常時録画、AIによる自律操作。

## 実装承認後の検証ゲート

| ID | 検証 | 合格基準 | 主な実施手段 |
| --- | --- | --- | --- |
| G1 | iPhoneの信頼・PWA導入・証明書更新 | 無料かつMacなしで真正性を確認してCA導入。警告なしのHTTPS、ホーム画面内登録、WSS、再起動・証明書更新後も正しく接続。期限切れ・別CAは拒否 | 実機iPhoneとPC。CA受渡し・フィンガープリント・信頼削除まで記録 |
| G2 | 認証・ブラウザ攻撃・失効 | 未登録／失効credential、別Origin、CSRF欠落、他端末sessionId、再利用コード、期限切れを拒否。既存WSSも失効で閉じる | API負例と実ブラウザ。必要な部分にローカルZAP等。正規対象だけを試験 |
| G3 | LAN境界・設定変更 | 登録NIC/IP/Private以外で受信しない。Wildcard/IPv6/追加endpoint/Firewall不明で起動拒否。通信中の変更でも停止 | 隔離した試験環境でPublic切替、NIC変更、VPNアダプター、異なるサブネット・別LAN端末から試験 |
| G4 | アプリ切替・入力 | 日本語200文字、改行、絵文字、英数字の往復が一致。IME確定中に送らない。対象消滅・前面化拒否で入力しない。管理者アプリは拒否 | メモ帳、Chromeの入力欄、Explorer等。Win32/UIAテストとiPhoneの実キーボード |
| G5 | ファイル安全性 | 正常操作・ごみ箱・100 MiB転送と、path traversal、UNC、ADS、reparse point、hardlink、上書き競合、途中切断を検証 | 一時フォルダと合成データ。ルート外に既知の検査ファイルを置き、変更されないことを確認 |
| G6 | ConPTY | PowerShellの入出力、UTF-8、resize、Ctrl+C、対話アプリ、改行貼付、出力量制限、子プロセス終了が機能 | コマンド／出力のfixtureと実機iPhone。CPU・メモリも監視 |
| G7 | noVNCとUltraVNC | 通常アプリモード、ループバックのみ、非昇格、モニター/DPI/入力が動作。画面終了・ロックで停止。外部向けVNC/HTTP/relayなし | WindowsとiPhone。待受け検査、認証付きWSS、許可端末／別端末の比較、遅延測定 |
| G8 | 切断・復帰・停止 | iPhone背景化・ロック・Wi-Fi切断で二重実行なし。PCロックでPTY/VNC終了。トレイ停止・端末失効で接続と操作枠を除去 | 状態遷移テストと実機。停止処理の検出後1秒以内を目標 |
| G9 | オフラインとUX | WANを遮断した試験LANで起動・認証・全MVP操作が可能。アプリ由来の外部DNS/HTTP/relay通信なし。下記性能・体験基準を評価 | プロセス別通信記録と実機タスク。OSや他アプリの通信は区別 |

G3/G9で実際のインターネット公開はしない。送信元変換や誤転送を試す場合は所有する隔離ネットワークで模擬し、ルーターのWANポート開放を検証手段にしない。他人のLAN端末や公開IPを無断で走査しない。

## AIで検証できる範囲と人が必要な範囲

| AI主導で自動化する | 実機・人による確認が残る |
| --- | --- |
| 型・schema・APIの認可負例、固定ネットワーク設定の検査 | iOSの証明書導入と信頼操作、PWAのホーム画面追加 |
| Playwrightによる画面状態、タッチ想定サイズ、キーボード操作、接続断 | 日本語IME、実際の貼付許可、Filesへの保存、iOSの背景停止と復帰 |
| 一時領域でのファイル安全性・並行変更試験 | 親指の届き方、読みやすさ、誤タップ、画面操作の感覚 |
| Windows上の対象アプリ／ConPTY／VNCの結合試験 | UACやPCロックで触ってはいけない境界の確認 |
| ログと通信記録からの外部依存検査 | 自宅ルーターのDHCP予約可否、実Wi-Fi品質 |

PlaywrightのiPhoneエミュレーションはviewportやuser agent等を模擬するもので、実際のiOSキーボード・証明書ストア・PWAライフサイクルの証明にはならない。[Playwright Emulation](https://playwright.dev/docs/emulation) 自動検証はWindows上でローカル実行できる。GitHub ActionsやクラウドのiPhoneテストサービスは必須にしない。

## 遅延・快適さの目標

以下は**未測定の合格目標**であり、実績値ではない。1回の最速値だけを報告しない。

| 指標 | 初期目標 | 測定範囲 |
| --- | --- | --- |
| タップの視覚的反応 | 50 ms以内 | PWA内の押下フィードバック。処理完了とは区別 |
| 軽いAPI操作 | p95 150 ms以下 | iPhone要求送信から結果受信。重いアプリのcold start・大量I/Oは除く |
| ターミナルecho | p95 150 ms以下 | 入力からechoが描画されるまで。コマンド自体の処理時間は別 |
| 画面操作の反応 | p95 200 ms以下を目標 | 入力から対応する変更フレームの描画まで。RFB受信時刻だけで代用しない |
| 接続復帰 | 到達可能になってから3秒以内を目標 | 再認証が不要なケースの状態再取得。復帰中の入力は禁止 |
| 重要操作の誤実行 | 二重実行0回 | 切断と復帰、タイムアウト、二重タップ、アプリ切替の反復試験 |

計測条件は同一PC・同一iPhone・同一APで固定し、PC有線／無線、電波状態、解像度・DPI、iOS、OSS版を記録する。100回以上の軽い操作から中央値・p95・失敗率を算出し、通常負荷と転送併用時を分ける。テスト用Windows画面の色変更等を用いて「要求に対応する描画」を認識し、クライアントの単一時計で測る。高速度撮影が利用できれば体感遅延の補助にするが、新規購入を前提にしない。

Chromeリモートデスクトップとは、単なるネットワークpingではなく同じ実タスクで比較する。

1. 2つのアプリを交互に10回切り替える。
2. 日本語200文字を入力し、訂正して送る。
3. 既知のファイルを探し、名前を変更し、コピーする。
4. PowerShellで一覧を取得し、結果の一部をコピーする。
5. 保存ダイアログを処理する。

各タスクを複数回行い、所要時間、タップ数、誤操作、文字化け・欠落、主観的負担を記録する。専用UIの主要タスクは中央値の所要時間を30%以上短縮することを初期の価値仮説とする。画面操作だけが遅い場合は原因を記録し、Sunshine/Moonlightを再比較する。安全機能を外して目標を達成しない。

## 実装順序の提案

1. **承認後の技術検証**：G1のTLS/PWA、日本語入力、非昇格のウィンドウ操作、noVNCの小さい接続確認。ここではユーザーの実ファイルを変更しない。
2. **接続・安全基盤**：認証、LAN不変条件、失効・停止、操作ID、最小のトレイ。
3. **日常の専用UI**：アプリ、ファイル、入力。契約テストと一時データで検証。
4. **端末・画面**：高い操作権限を持つ機能を利用枠とともに統合。
5. **常用前の受入れ**：全ゲート、実機のタスク比較、オフライン、設定変更、証明書更新・削除手順。

工数は実機検証前に確定しない。現時点では「短いPoC→継続判断→MVP」を推奨するが、PoCも実装に含まれるため、この設計依頼の範囲では開始していない。
