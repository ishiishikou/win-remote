# PWAとWindowsユーザーセッション内エージェントを推奨する

## 状態

設計上の推奨。ユーザーによる実装開始の決定ではない。現在の依頼は設計・実現可能性評価・資料保存までであり、実装IssueやPoCは開始していない。

## 背景

iPhoneでWindows画面を縮小表示する方式では、小さいクリック対象、日本語入力、遅延が負担になる。Windows Home、自宅LANのみ、完全無料、App Store公開不要、AI主導で開発・検証しやすいことが制約となる。

## 推奨する選択

1. iPhone側はホーム画面から開くPWA。アプリ・ファイル・入力・端末を目的別のUIに分ける。
2. Windows側はC# / .NET 10 LTSのトレイエージェント。現在のログインユーザーとして非昇格で実行する。
3. 同一オリジンのHTTPS/WSSで接続。専用CA、端末登録、パスフレーズ、短い操作枠を使う。
4. ターミナルはxterm.js + ConPTY。画面操作は必要時だけnoVNC + UltraVNCを通常アプリ／ループバック限定で起動する。
5. 外部接続機能を持たず、登録LAN・NIC・IP・Firewall条件が変わったら停止する。

## 理由

PWAはMacやiOSアプリの署名更新を主開発フローに持ち込まず、Windows上のブラウザで機能を分けて検証できる。OSの実機特有動作は別途検証する。Windows専用エージェントは.NETとWin32の組合せが自然で、GUI・ファイル・クリップボードを扱いやすい。

普段の操作をデータAPIにすると、画像の転送・圧縮・座標指定を多くの操作から省ける。これは低遅延を期待する設計上の推論であり、既存サービスを上回る実測結果ではない。画面と端末の処理は成熟したOSSとWindows機能を使う。

## 検討して採用しなかったもの

- 自作ネイティブ／クロスプラットフォームiOSアプリ：無料署名更新とビルド環境の負担が残る。
- 標準RDP：Windows Homeをホストにできない。非公式回避を採用しない。
- 画面転送だけの既存アプリ：スマホ用に機能を組み直す目的を満たさない。
- Sunshine/Moonlightを標準搭載：画面性能には期待できるが、別クライアント・別認証・複数ポートと暗号化設定の検証が必要。補助画面だけの初期用途には負担が大きい。
- RustDesk：画面操作代替として有効だが、Direct IPと外部依存停止・暗号化を個別に検証する必要がある。専用UIは別途必要。
- Guacamole：この1台用途では構成要素が多い。
- 管理者サービス：権限が広く、ユーザーのデスクトップとの分離も必要になる。
- 自作WebRTC配信：エンコード、シグナリング、ICE、入力経路の実装・検証が増える。既存OSSの性能を確認してから判断する。

根拠資料と比較は[評価資料](../design/overview.md)および[調査記録](../design/research.md)。

## 受け入れるトレードオフ

- iPhoneへのローカルCAの信頼登録と証明書保守が必要。
- バックグラウンド常時接続や自動clipboard同期を前提にできない。
- UAC、ロック画面、管理者アプリの操作は対象外。
- noVNCの低遅延は未実証で、重い画面操作には限界があり得る。
- 自由なシェルと画面操作はWindowsユーザー相当であり、限定APIの許可リストに閉じ込められない。
- LAN限定の誤設定防止は多層化できるが、管理者や信頼済み端末による意図的な中継を完全には防げない。

## 再検討条件

| 条件 | 対応 |
| --- | --- |
| CAを安全・無料・Macなしで導入／更新できない | PWAの採否を見直す。HTTPや証明書検証無効化へ逃げない |
| iPhoneの日本語入力・clipboard・復帰が実用性を満たさない | UIの入力方式を修正し、それでも不十分ならネイティブの運用条件を再検討 |
| UltraVNCの非昇格・ループバック運用が成立しない | 画面機能を止め、別の既存バックエンドを比較する。管理者常駐を黙って追加しない |
| noVNCの画面遅延が受入れ基準を満たさない | Sunshine/Moonlight等を実測比較 |
| シェルの厳密な隔離が必要になる | 別アカウント／実行環境へ分離し、同一デスクトップ操作との両立条件を再設計 |
| 複数ユーザー・WAN・無人ログインが必要になる | この設計を小さな設定変更で流用せず、新しい脅威モデルと判断記録を作る |

## 次に判断すること

ユーザーがこの方向での実装を承認した後、[検証ゲート](../design/mvp-validation.md)の小さいPoCから開始する。iPhoneの機種・iOS、主要アプリ、DHCP予約可否、CAの受け渡し方法を確認し、実測結果を同じ資料に追記して採否を更新する。
